# Bakaiti redesign implementation brief — 2026-10-28

Objective: redesign the real Next.js social messaging application for Gen Z, while auditing README claims, fixing concrete interaction defects, and keeping service-dependent features honest. Main user focus: a fast, expressive, inviting place for conversations and a social circle. Existing signup email OTP followed by username/password login must stay functional. User reports Gmail SMTP, confirmation and OTP template configured; deployed callback URLs deferred until deployment. No changes to production Supabase settings or real accounts.

Aesthetic direction: a late-night digital clubhouse. Ink canvas, lilac conversation/action surfaces, sharp lime Pulse accents, oversized Space Grotesk section headings against readable Plus Jakarta Sans body copy. Preserve Bakaiti identity and violet family but remove generic neon glow overload, fake nightlife imagery/statistics and redundant headers. Memorable signature: small lime Pulse/status capsules and a bold lowercase-feeling Bakaiti wordmark with playful concise copy. App utility wins over decoration inside long threads/forms. Avoid dashboard-stat-card grids and fake live numbers.

Canonical runtime colors are owned in src/app/globals.css. Suggested system: background #0D0F14, surface #151821, elevated #1D202B, border #2A2D38, text #F5F3FA, secondary #A6A7B7, lilac primary/accent #B8A0FB, lime secondary #D7F87B. Brand buttons use dark ink text against lilac/lime for contrast. Existing Space Grotesk and Plus Jakarta Sans are sufficient: no new font dependency. Muted text still readable, no raw technical implementation terms in product copy. English interface, no Japan-specific product requirement.

Desktop: consistent 240px sidebar and 64/72px header with matching content offsets, messaging-first navigation, active states, real unread badges, account menu/Pulse. Feed with center stream and useful right rail only with actual data or navigational content. Chat with inbox column + thread, purposeful empty state, searchable conversations, clear unread filter, clear-back mobile navigation. Mobile: safe-area bottom navigation, 44px actions, one primary content column, scroll ownership per panel, no redundant mobile headers in thread. Auth: expressive split shell on desktop, compact form-first mobile; keep actual forms/OTP accessible and usable.

Content: remove fake scores, fake engagement, always-online avatars and toast-only pretend poll/audio functionality. Zero is a real value, missing state is a real state. Only show enabled buttons if they perform a real implemented action. Calling UI is not release-ready (incoming signaling/media track controls incomplete): do not claim working calls, do not add fake calls. Existing useful primitives Button, Dialog, DropdownMenu, UserAvatar, PulsePicker, Sonner own their capabilities. Extend shared owners, not duplicated local controls. Search clear, URL state, stale-result safety, loading/error/empty feedback, keyboard focus, disabled/busy and reduced motion are required where touched. Never native confirm/alert; use existing Dialog for destructive user actions.
